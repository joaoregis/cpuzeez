# Security review, 2026-11-09 (after `1.0.0-snapshot.1`)

A pass over the whole tree after the contributor fixes (joaoregis/cpuzeez#4, #5) were integrated, looking for the same bug classes elsewhere and for anything the earlier reviews missed. Method: every place where data from outside the process becomes an action (a process start, a file write, a URL opened, an export), every path a more privileged process opens, and the [audit guide's](../audit/README.md) checklist. Fixes are in the commit that adds this file; the soak and the long randomized campaign that ran the same night are reported at the end.

## Findings

| ID | Severity | Where | What | Status |
|---|---|---|---|---|
| R1 | Medium | `src/executor.rs`, `platform::proc_ops::dump` (Windows) | The elevated copy wrote a memory dump to a predictable name (`cpuzeez-pid<pid>-<seconds>.dmp`) in the user's temp folder with `File::create`, which overwrites an existing file and follows a planted link | Fixed |
| R2 | Low–Medium | `src/update.rs`, the update bar | URLs from the releases answer were used as given: a download URL starting with `-` would be read by `curl` as an option, and the release page and asset URLs are opened by the update bar, where a `file:` URL or a local path would run a program; `curl` followed redirects to any protocol | Fixed |
| R3 | Low | process, performance and sensor exports; table copy | Text from other programs (process names, paths, window titles, sensor labels) went into CSV and copied TSV as is; a cell starting with `=`, `@`, `+`, `-` is a formula in Excel/LibreOffice (CSV injection) | Fixed |
| R4 | Low | `system.rs`, `system_perf.rs` | *Export CSV/JSON* wrote `processes.csv`, `processes.json` and `performance.csv` to the **current directory**: `System32` or `/root` in an elevated copy, a fixed name in whatever folder the app started in | Fixed |
| R5 | Low (Linux) | `platform::users::send_message` | The message for another session went to `notify-send` as a plain argument; one starting with `-` was read as an option | Fixed |

### R1: the elevated memory dump

*Create dump file* runs in the elevated copy (UAC on Windows; the action does not exist on Linux and macOS). The copy runs with the user's environment, so `temp_dir()` is the user's own `%TEMP%`, which anything running as the user can write. The file name was the target PID and the current second, both knowable in advance, and `File::create` (`CREATE_ALWAYS`) overwrites whatever has that name and follows a link there. A program running as the user could plant a link for the next few seconds' names and, when the user dumps a process, have the administrator copy truncate and overwrite a file of its choice with the dump's bytes (the same class as #5's handoff marker, on the Windows side).

Fix: the name carries an unpredictable token (`tempdir::token`), and the file is opened with `create_new` (`CREATE_NEW`), which fails if anything, including a link, already has the name. Residual: a same-user program that can replace the user's whole `%TEMP%` folder with a junction while the dump is written; the user's own folder cannot be defended against the user's own programs, and Microsoft does not treat UAC as a security boundary. The dump itself is meant for the user, and lands where they can read it, as Task Manager's does.

### R2: URLs from the releases answer

The update check reads GitHub's answer over TLS, so exploiting this needs a compromised GitHub account or API, or a trusted-CA interception. Still, nothing in that answer should be able to become a `curl` option or a local program. Fix: `https()` keeps only plain `https://` URLs without spaces or control characters (anything else drops the asset, or falls back to the project page for the release page), and both `curl` calls pass `--proto =https --proto-redir =https`. The SHA-256 check is unchanged: a forged release still needs a matching `SHA256SUMS.txt` from the same answer, which is the accepted limit of unsigned releases ([ADR 0009](../adr/0009-releases-stay-unsigned-for-now.md)). Test: `release_urls_are_https_only`.

### R3: spreadsheet formulas

`report::spreadsheet_safe` prefixes `'` to text that a spreadsheet would read as a formula, and leaves numbers such as `-3.5` alone. Applied to the process CSV, the performance CSV, the sensor view export and the table copy. Test: `spreadsheet_formulas_are_neutralised`. Not applied to JSON exports (no formulas) or reports (HTML is escaped).

### R4: exports in the current directory

`settings::export_path` puts each export in `exports/<date-time>-<name>` inside the data folder (or a fresh private folder when there is none), and the message shows the full path. The *Privacy & data* page does not list `exports/` as a category yet (noted for 1.1.0).

### R5: `notify-send`

The arguments now start with `--`.

## Checked and found sound

- **Every process start** (`Command::new`, 31 places): fixed program names or absolute paths; arguments from validated actions (service and startup names, kernel modules from an allow-list), `--` before service units; `sh -c` and the Windows shell only for *Run new task*, whose whole purpose is to run what the user types. No `.bat`/`.cmd` is started with outside arguments.
- **Fixed names in shared temp folders**: all remaining ones are in tests (`#[cfg(test)]`) or ignored live probes.
- **SQLite**: every statement uses bound parameters.
- **HTML session reports**: every string escaped; covered by robustness tests.
- **Diagnostics bundle**: uses the masked report.
- **Session folder names** from a game's name: reduced to `[A-Za-z0-9_-]`, 48 characters.
- **MangoHud install**: the package name comes from a fixed table.
- **KMS ioctls**: buffers sized from the kernel's own counts, capped; a count that grows between the two calls leaves zeroed modes, which decode as no mode.
- **The updater, handoff marker and PresentMon** after #4, #5 and the follow-ups: as described in the [threat model](threat-model.md).

## Informational (by design, documented)

- *Run new task* runs any command the user types, optionally as administrator (the OS asks).
- The elevated copy accepts `--elevated-op` from anyone who can start the program; the OS consent prompt is the boundary, and the operation list is closed and validated.
- A memory dump contains the target process's memory and is written where the user can read it.
- Releases are unsigned; updates trust GitHub's answer plus `SHA256SUMS.txt` from the same release.
